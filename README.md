# 牛来量化

A 股选股 → 因子漏斗 → 交易的自用系统。每天在牛来策略时段从几个股池里拉股票，用一串可自定义的因子层层过滤，按打分取前几名下单，持仓按卖出规则自动卖出。所有操作和设置都在本机网页上完成。默认运行在模拟盘。

详细说明（每个页面、因子库、插件写法、接口格式）见 [docs/GUIDE.md](docs/GUIDE.md)。

## 功能一览

- **股池接入**：牛来股池（竞价多头、晨星量化、竞价阿尔法、十点半、黄金两点半）、自选股、akshare 涨停池和强势股池，也可以通过标准数据接口接入任意第三方股池
- **买入漏斗**：分层过滤，每层放一个或几个因子，选「全部满足」或「任一满足」，最后按打分取前 N 名
- **卖出因子链**：止损、止盈、持有天数到点卖、冲高回落等，逐层检查，任一层触发就卖
- **多套策略**：买入、卖出策略都能存多套，每个股池可以单独绑定一套
- **筛选过程可视化**：每次运行每一层剩多少只、每只票在哪一层因为什么被淘汰
- **插件**：放进 `plugins/` 的 Python 文件自动加载，可注册因子、数据源、推送渠道
- **交易**：模拟盘、演练、实盘三种运行模式；实盘对接 Windows 下单程序，自动对账
- **推送**：钉钉、企业微信、飞书、Server酱、PushPlus、Telegram
- **回测**：按股池存档回放，按股池分开统计
- **对外 API**：读状态、读写策略、推送外部因子和数据；不提供任何下单接口

## 快速开始

需要 Python 3.11 或更新版本。

### Windows

1. 安装 Python 3.11+，安装时勾选 "Add to PATH"。
2. 双击 `scripts\start.bat`，第一次会自动建虚拟环境并安装依赖。
3. 浏览器打开 http://127.0.0.1:8081 。关闭命令行窗口程序就停止。

```bat
scripts\start.bat                  :: 启动网页 + 定时任务
scripts\start.bat run --no-trade   :: 只跑一次选股，不下单
scripts\start.bat test             :: 单元测试
```

### Linux / macOS

```bash
scripts/start.sh                  # 启动网页 + 定时任务
scripts/start.sh run --no-trade   # 只跑一次选股，不下单
scripts/start.sh test             # 单元测试
```

网页只监听本机 `127.0.0.1:8081`。程序跑在云端机器上时，在自己电脑上做端口转发：

```bash
ssh -N -L 8081:127.0.0.1:8081 用户@云端机器
```

### 第一次使用

1. 打开「设置 → 数据源」，填入股池数据源的 API KEY，点「测试连接」。
2. 打开「设置 → 股池列表与别名」，勾选要用的股池。
3. 打开「买入 → 买入策略」「卖出 → 卖出策略」，套用一个模板或自己搭。
4. 在「买入 → 选股结果」点「只选股（不交易）」，看漏斗结果是否符合预期。
5. 需要推送时，在「设置 → 推送」填写渠道并点「发测试消息」。

## 网页

界面是单个 HTML 文件，不需要前端构建。为了好维护，源码按功能拆成 `qfpy/web/index.html`（页面骨架：HTML + CSS + include 占位符）加 `qfpy/web/parts/*.js`（24 个 JS 片段，一个功能一段）；服务端返回首页时按占位符顺序把这些片段原样内联回去，浏览器拿到的仍是完整单页（与拆分前字节级一致），没有外链、没有额外请求，也不需要打包工具。注意直接双击磁盘上的 `index.html` 会缺少片段内容，正式使用走 `python -m qfpy serve`（8081）。宽屏铺满，手机宽度自动变成单列。深浅两套主题。

顶栏始终显示：自动交易开关、当前运行模式、当前生效的买入和卖出策略。

| 一级 | 子页 |
|---|---|
| 首页 | 大盘指数、市场情绪、股池走势 |
| 买入 | 买入策略、股池分配、选股结果 |
| 卖出 | 卖出策略、股池分配、卖出结果 |
| 账户 | 资金与持仓、仓位与风控 |
| 回测 | 选策略、选股池回放 |
| 设置 | 数据源、股池列表与别名、时段与补录、下单程序、推送、对外 API、插件、首页、运行模式 |
| 日志 | 推送记录、运行日志、系统信息 |

地址写成 `#大页/子页`（如 `#buy/results`），可以直接收藏。

### 首页

- **大盘指数**：上证、深证成指、创业板指、科创50、沪深300 的点位、涨跌幅、成交额和分时小图
- **市场情绪**：涨跌家数、涨跌停家数、两市成交额
- **股池走势**：按股池切换；左边成分股列表，右边单只票详情（分时或日K、各项指标、在买入策略里走到哪一层、打分明细；有持仓时显示离止盈止损还差多少、哪天到期卖出）
- 交易时段默认每 15 秒自动刷新，收盘后 5 分钟一次；刷新只更新数字和图，不打断正在看的内容

### 买入

- **买入策略**：编辑漏斗的层和因子，参数全部点选；保存前显示和上一版的差异；「设为生效」后从下一次选股起按这套来
- **股池分配**：每个股池选用哪套买入策略、新入池怎么算；拖动调整股池优先顺序（一只票同时在几个池里时归排在前面的池）
- **选股结果**：所有运行记录合成一张表，可按股池筛选；上方是按股池的汇总；点一只票展开每层的通过情况和跨天的级别变化（候选、重点、买入）；可在「历史记录」里选某一次运行看漏斗图；页面底部可以手动运行

### 卖出

- **卖出策略**：编辑卖出因子链、默认参数和按股池覆盖的参数
- **股池分配**：每个股池选用哪套卖出策略，「启用卖出检查」开关
- **卖出结果**：每次卖出检查逐只列出持仓的现价、浮盈、按哪套策略、触发了哪一层、结果和原因；「立即检查卖出」在这一页顶部

### 账户

- **资金与持仓**：资金、持仓、委托记录、手动下单和撤单、收益曲线、胜率、回撤、已平仓明细
- **仓位与风控**：单笔上限、每日买入金额、黑白名单、同一行业最多几只

### 设置

所有配置都能在网页上改，保存前校验，写回 `config/pipeline.toml`（旧文件留成 `.bak`），立即生效，不用重启。敏感字段显示成掩码，日志和推送里也是掩码。每个数据源和推送渠道旁边都有「测试连接 / 发测试消息」，用表单当前填的值去试，不用先保存。

## 牛来策略时段

默认时段（「设置 → 时段与补录」可以增删改）：

| 时段 | 股池 |
|---|---|
| 09:27–09:35 | 竞价多头、竞价阿尔法、晨星量化、自选股 |
| 10:30–10:35 | 十点半 |
| 14:30–14:35 | 黄金两点半 |

- 时段内跑完整链路：股池 → 买入漏斗 → 下单或只记信号。是否真的下单看自动交易开关
- 股池还没出数据时每 60 秒重试，到时段结束还没数据就推送提醒
- **补录**：启动时如果当天已经错过某个时段，自动补跑并标成「补录」；默认补录不下单
- 卖出检查和卖出前提醒的时刻在卖出策略里设置，自动加入定时任务

## 三个开关

| | 自动交易开关 | 运行模式 | 自动获取持仓 |
|---|---|---|---|
| 管什么 | 系统要不要自己发委托 | 委托发到哪里 | 资金和持仓从哪来 |
| 选项 | 开 / 关 | 模拟盘（本地模拟成交）、演练（只生成请求不发出）、实盘（发给下单程序） | 关：在账户页手动维护；开：从下单程序读取 |
| 在哪改 | 网页顶栏 | 设置 → 运行模式 | 账户页顶部（只有实盘能打开） |
| 默认 | 关 | 模拟盘 | 关 |

- 自动交易关闭时照常选股、做卖出判断和推送，委托只记为「本应下单」的信号；关闭时同时撤掉本系统当天还没成交的自动委托，手动单不撤
- 手动下单和撤单不受自动交易开关限制，但照样过风控

## 买入漏斗和卖出因子链

两者是同一套结构：**若干层，每层一个或多个因子，按「全部满足 / 任一满足」组合**，层和因子都能单独开关、调顺序、改参数。买入漏斗一层层淘汰候选，最后按打分取前 N 名；卖出链对每只持仓逐层检查，任一层触发就卖。

### 因子库

12 类：价格涨跌、量能换手、均线与分时、技术指标、涨停板、形态信号、竞价与资金、股池来源、基本面与排雷、持仓与卖出、高级/自定义公式、外部因子。每个因子标明盘中实时还是盘后更新、回测能不能用。

拿不到数据时因子一律报「数据缺失」，不当成 0 也不当成通过。买入漏斗里每个因子可以选数据缺失时「淘汰」（默认）或「放行」。

### 模板

- 买入：竞价强势、尾盘黄金两点半、稳健低吸、只用表达式
- 卖出：经典三件套、隔日尾盘卖、趋势跟踪、盘中走弱就卖

### 在配置文件里写

```toml
[[buy_funnel.layers]]
name = "硬性过滤"
mode = "all"            # all = 全部满足；any = 任一满足
factors = [
  { kind = "exclude_st" },
  { kind = "min_amount", params = { min_yi = 2 } },
]

[[buy_funnel.layers]]
name = "突破（任一）"
mode = "any"
factors = [
  { kind = "expr", label = "上穿 5 日线", params = { expr = "close > ma5 and close[1] <= ma5[1]" } },
  { kind = "above_vwap" },
]

[[sell_funnel.layers]]
name = "止损"
factors = [{ kind = "stop_loss", params = { pct = 3 } }]

[[sell_funnel.layers]]
name = "冲高回落"
mode = "all"
hold_skippable = true
factors = [
  { kind = "drawdown_from_high", params = { pct = 3 } },
  { kind = "expr", params = { expr = "pnl_pct > 2" } },
]
```

### 卖出规则

- 止损层永远最先检查，点「保留」也挡不住
- 遵守 T+1：当天买入的部分当天不卖，零股一次卖完；只卖「已确认」的持仓，数量不超过可卖数量
- 止损、止盈、持有天数、到点卖出的参数留空时取卖出策略的默认值，也可以按股池覆盖。例如黄金两点半持有 1 天、14:45 卖，其他持有 3 天、14:50 卖
- 卖出表达式除了行情字段，还能用持仓字段：`pnl_pct`、`held_days`、`avg_cost`、`quantity`、`sellable`、`now_min`、`high_since_buy`、`drawdown_since_buy_pct`
- 拿不到价、因子出错、止损层缺数据时，这一轮不卖也不算「没触发」，记日志并推送

### 人工保留

在账户页持仓表点「保留」，弹窗里选挡多久，模式存在这只票的保留标记里，逐票独立：

- **到下一次检查**：只跳过**这一次**自动卖出，跳过后标记自动失效（原来的逻辑）。
- **到该交易日结束**：当天剩下的卖出检查都挡，跨到下一个交易日自动失效。
- **到手工解除**：一直挡，直到你点「取消保留」。

三种都**挡不住止损**：止损层永远最先检查，碰到止损照卖。命令行也能用 `hold 代码 --mode ...` 指定。

后两种由独立插件 `plugins/hold_policy/` 实现（按交易日历判断日终，日历来自 `plugins/trade_calendar/`）。插件没加载或被禁用时，选后两种也只会按「到下一次检查」处理。

到点卖出前 5 分钟推送「即将卖出」提醒，列出每只票是否已保留。

### 股池绑定策略

每个股池可以指定自己的买入、卖出策略，没指定的用当前生效的那套。一只票同时在几个池里时，按股池优先顺序取第一个。按股池覆盖的卖出参数属于卖出策略本身：绑定决定用哪套卖出链，覆盖只改这套里的数字。

## 账户和交易

### 手动账本

自动获取持仓关闭时，资金、持仓、委托都在账户页手动维护：可以填可用资金，增删改持仓，补记在券商客户端里下的单。模拟盘也能手填，手填的部分当作转入转出，收益率不会因此跳变。

### 委托记录

系统发出的每笔委托（包括只记信号、风控拦截的）都自动记下时间、代码、方向、价格、数量、状态、成交、来源策略和合同号，每个运行模式一本。

### 手动下单和撤单

- 输入代码后显示名称、现价、涨跌停价、持仓和可卖数量，提交前弹确认框
- 市价单按现价上下 1% 换成数字限价，不超过涨跌停价
- 手动单照样过风控；撤单只按合同号撤

### 风控

- **只管买入**：单笔上限、每日买入金额、白名单、黑名单、同一只票每天只买一次、整手、同一行业最多几只
- **买卖都查**：代码格式、数字限价和整数股数、涨跌停价范围、偏离参考价、交易时段
- 不限每日委托笔数；卖单不受金额限制

### 实盘对接

实盘通过 Windows 上的下单程序操作同花顺客户端。本系统只调用下单程序的下单、撤单和几个只读接口（状态、快照、刷新），其余接口在发请求前就被拦下。

1. 在下单程序所在电脑上登录同花顺并启动下单程序。
2. 在「设置 → 下单程序」填写地址和口令，点「测试连接」，连接和口令都通过才算打通。
3. 先用演练模式跑几天，委托记录里能看到完整的请求内容。
4. 在「设置 → 运行模式」选实盘，再打开顶栏的自动交易开关。

### 自动对账

- 交易时段定时读取下单程序的状态和快照（持仓、当日委托、当日成交）；下单或撤单后立即同步
- 在途委托按合同号匹配，没有合同号时按代码、方向、数量、价格、时间匹配，并按成交情况更新本地持仓
- 本地和券商持仓一致时自动标「已确认」；连续两次强制重扫都对不上，才标「结果未知」，暂停这只票的自动卖出并推送
- 在券商客户端里手动卖掉的票，对账时会识别出来并平掉本地持仓
- 超时、断线一律不自动重试

| 持仓状态 | 怎么来的 | 怎么变成已确认 |
|---|---|---|
| 已确认 | 对账一致，或手动核对过 | — |
| 买入待确认 | 买单已报，等成交 | 对账看到成交后自动确认 |
| 卖出待确认 | 卖单已报，等成交 | 对账看到成交后自动减仓或平仓 |
| 结果未知 | 超时、断线、没拿到合同号，或连续对不上 | 对账找到委托或数量一致后自动处理；否则推送请人工核对 |

只有「已确认」的持仓会自动卖。下单程序没连上时对账停住，连上后自动补对账，也可以在账户页点「核对」按实际股数登记。

## 回测

- 每次选股和每个交易日 15:10 自动存档各股池的成分股，存在 `data/pool_archive/`
- 回测页选买入、卖出策略和一个或几个股池，每天只在当天存档的成分股里选股；结果按股池分开统计（收益率、最大回撤、成交笔数、胜率）并给合计
- 没有存档的交易日不选股，结果里列出这些日期；实验性因子在回测里跳过
- 回测只用日K，分时类因子无法重现，结果只作参考

## 扩展

### 自定义因子

| 办法 | 适合 | 怎么做 |
|---|---|---|
| 形态信号 | 不想写公式 | 因子库「形态信号」，点选拼条件；格式和 tick-stock-panel 自定义信号 JSON 一样 |
| 自定义公式 | 字段比较、简单组合 | 因子选「表达式」，写 `close > ma5 and close[1] <= ma5[1]` |
| 外部因子：推送 | 结果在别的程序里算好 | `POST /api/v1/factor-results/<名字>` 推结果，例子 `examples/external_push.py` |
| 外部因子：拉取 | 已有 HTTP 服务 | 漏斗里放「外部因子（HTTP 拉取）」，例子 `examples/external_factor_server.py` |
| 插件 | 要写 Python 逻辑 | 复制 `plugins/example_single_file.py`，改 `kind` 和 `evaluate()` |

### 插件

插件是放进 `plugins/` 的 Python 文件或文件夹，启动时自动加载，可以注册三样东西：

- **因子**：继承 `qfpy.factors.Factor`，加 `@register_factor`
- **数据源**：继承 `qfpy.datasources.DataSource`，加 `@register_source`
- **推送渠道**：继承 `qfpy.notify.Channel`，实现 `send(title, text)`，加 `@register_channel`

```python
from qfpy.factors import Factor, Outcome, ParamSpec, register_factor

@register_factor
class MyGap(Factor):
    kind = "my_gap"
    title = "我的高开因子"
    cat = "price"
    sides = ("buy",)
    params = [ParamSpec("max_gap", 3.0, "高开不超过多少 %", "float")]

    def needs(self):
        return {"minute"}

    def evaluate(self, c, ctx):
        gap = c.fields.get("open_change")
        if gap is None:
            return Outcome.missing_data("没有开盘涨幅")
        ok = gap <= self.p["max_gap"]
        return Outcome(ok, gap, f"高开 {gap:.2f}%")
```

改完在「设置 → 插件」点「重新加载」，不用重启。`kind` 不能和内置因子重名。`plugins/` 里自带的几个示例只演示写法，不是推荐策略。

### 第三方数据：标准数据接口（qfdp v1）

按 [docs/GUIDE.md](docs/GUIDE.md) 第四部分实现几个 HTTP 接口，然后在「设置 → 数据源」添加一个「标准接口」数据源。能力按实现的接口自动识别：实时行情、分时、日K、指数、市场情绪、股池。不合规范的返回值直接报错，不会混进数据。示例服务：`python examples/data_provider_server.py`。

数据源自己独有的数字字段也能接进来，在「外部数据源字段」因子里先选数据源再选字段，或直接写进表达式。

### 对外 API（`/api/v1`）

- 用 token 鉴权，token 在「设置 → 对外 API」配置；没配置时所有请求返回 401
- 能做：读状态、持仓、运行记录、漏斗、卖出预览；读写策略、套用模板；管理数据源、推送外部因子和数据；重新加载插件；触发一次只选股的运行
- 不能做：没有任何下单、撤单、改自动交易开关或改风控的接口。没有 `/api/cancel`、`/api/order` 这类端点，撤单和下单只能在网页或命令行里点
- 可以设为只读
- OpenAPI 文档在网页的 `/api/v1/openapi.json`

## 命令行

`python -m qfpy <命令>`：

| 命令 | 作用 |
|---|---|
| `serve [--no-schedule]` | 启动网页和定时任务 |
| `run [--no-trade] [--date D] [--pools a,b]` | 跑一次完整链路 |

| `positions` | 看持仓 |
| `broker-status` / `broker-snapshot` | 只读查看下单程序状态和券商快照 |
| `notify-test [--channel]` | 发测试推送 |
| `backtest --start D --end D` | 日K回测 |
| `check-config` | 校验配置 |

## 目录
